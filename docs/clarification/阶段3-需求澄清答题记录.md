### 第一轮已确定的 5 个架构约束

1. **三元库存记账**（仓×SKU×货主）—— 对商派模型的第一个硬改造点
2. **货主维度贯穿财务单据** —— 补齐逆向发现的商派最大缺口
3. **金蝶作为记账权威源，OMS 作为业务对账与明细供给方** —— 财务模块裁剪为「对账+核销+排查」，凭证外推
4. **多租户对外门户** —— 商派无此能力，需新建租户隔离层
5. **PIPL 合规** —— 消费者个人信息字段需加密/脱敏/授权留痕（商派 orders 表有 ship_name/ship_tel/ship_mobile/ship_addr 明文存储 + modifier 脱敏方法，可作起点）

### ⚠️ 待澄清：Q4「沿用 PHP」的路线分叉

沿用 PHP 有两种截然不同的实现路径，工作量差 3-5 倍：

| 路径 | 做法 | 优势 | 风险 |
|---|---|---|---|
| **路径 A：Fork 商派代码改造** | 直接 clone ShopeX/OMS，在其 58 模块上做增量改造（加货主维度、裁行业模块、换矩阵中心） | 起步最快，60+ 业务模块与 711 表现成可用；Apache-2.0 允许闭源改造 | ① 继承 113 万行历史代码与自研 ECOS 框架，新人上手成本高；② **erpapi 强依赖商派矩阵中心（SaaS 网关）**，必须替换为自建 gateway，这是最重的改造；③ 大内核 ome 模块难以拆分，改造侵入性大；④ 长期技术债 |
| **路径 B：PHP 新架构自研** | 用现代 PHP 栈（Laravel / Hyperf+Swoole）按逆向文档重新设计域模型与表结构 | 架构干净、可按 DDD 分域、无历史包袱；可精准吸收商派 7 大机制精华 | 工作量接近全量重写；4-6 人做 4 条链路周期长 |
| **路径 C：混合** | 核心域（订单/库存/财务）用新架构自研，平台对接层 fork 商派 erpapi 改造复用 | 平衡：最难写的平台报文适配直接复用，核心模型保持干净 | 两套框架并存，需明确边界与集成方式 |

### 关键取证事实（第二轮新增，支撑路径决策）

1. **矩阵中心硬依赖**：`app/base/defined.php:21` 硬编码 `MATRIX_URL='https://matrix-gw-open.shopex.cn/'`；`caller.php center_call()` 携 `certi_id`（商派 license 证书）签名；仓库内 0 处平台签名/SDK 实现 → **开源 erpapi 脱离商派 SaaS 服务无法运行**。
2. **抖音缺失**：76 个 matrix 平台目录无 douyin/抖音；全仓库 grep 抖音 = 0。
3. **耦合度**：erpapi 1411 文件中 381 个直接调 ome 模型；matrix 映射层 645 文件中 156 个内嵌 ome 表读写 → 路径 C「只 fork 对接层」不成立。
4. **框架生态**：composer 仅 4 依赖，ECOS 全自研（MVC/队列/ORM/事件），87 star 无社区；但工程质量好（phpstan/phpunit/Sentry/Docker）。

## 决策汇总（截至 2026-10-23）

**技术路线**：路径 B —— PHP 新架构自研（Hyperf/Laravel，spike 后定），商派代码仅作参考实现。

**三大模型地基改造**（相对商派）：
1. 库存记账 `仓 × SKU × 货主` 三元 + 借调规则表与借调流水
2. 货主维度贯穿全业务单据（含财务，补齐商派最大缺口）
3. 租户级行隔离（品牌方门户 + SaaS 化预留）

**MVP 范围**（4 条链路）：正向履约主链路 / 多货主库存记账与同步 / 售后 / 采购入库
**后置**：经销 B2B（dealer/sales）、跨境申报、自助分析、WMS 库内作业层、pos/wap/tbo2o

**继承商派 7 大机制**：审单插件链（位标记改结构化原因表）、合单指纹+缓冲窗、拆单策略注册表（16 策略可插拔）、预占独立流水+Redis Lua、api_log/api_fail 双表分级重试、售后三段式、元数据驱动 CRUD。

**自建替代**：平台 gateway（替代商派矩阵中心）+ 6 平台适配器（抖音从零）+ 多 WMS 路由 + 金蝶数据供给层 + 泛微 OA 审批集成。
