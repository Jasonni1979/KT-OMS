## 轮次一 · 架构骨架（8 问，全 P0）

> 这 8 个问题的答案决定「系统边界、数据模型根基、技术栈」，答完就能出新架构草图。

### Q1【P0】自研系统的范围边界到哪里？
- A. 只做 OMS（订单/库存/售后），仓储继续用通天晓 WMS，仅做推仓对接
- B. OMS + 库存中台（含多仓库存记账、调拨、盘点），WMS 作业层仍用第三方
- C. OMS + WMS 全栈自研（含库内作业、波次拣货、PDA）
- D. 分阶段：先 A/B，二期扩到 C

**影响**：决定是否要逆向吸收商派 wms/tgkpi/taoguaninventory 等模块；决定表数量与团队规模量级。

### Q2【P0】库存是「一盘货共享」还是「按货主严格隔离」？
- A. 严格隔离：每个货主（品牌方/凯淳自购）的库存物理分账，不可互相占用
- B. 逻辑隔离 + 允许借调：默认分账，可配置跨货主调拨/共享比例
- C. 一盘货：全部库存共享，只在财务结算时区分归属
- D. 混合：部分品牌一盘货、部分品牌严格隔离（需按品牌配置）

**影响**：这是数据模型的地基。商派的 branch_product（仓×SKU）单货主模型撑不住 A/D，必须加货主维度做成 `仓×SKU×货主` 三元记账，改动面极大，必须先定。

### Q3【P0】货权主体有哪些？谁在法律上拥有库存？
请列举，例如：
- 凯淳自有采购（买断经销）→ 货权在凯淳
- 品牌方委托代销（货权在品牌方，凯淳只收服务费/佣金）
- 贸易公司主体（凯淳体系内的不同法人？）
- 是否有跨境/保税仓货权特殊性

**影响**：决定 organization 组织树的节点类型设计、财务单据的货主维度（逆向发现的商派最大缺口）、以及转单拆单是否要按货权主体分组。

### Q4【P0】技术栈方向？
- A. Java + Spring Boot（生态成熟、招人容易、企业级首选）
- B. Go（高并发库存/队列场景性能好、部署轻）
- C. Node.js + TypeScript（前后端同构、与 K-AIDE 技术栈可能统一）
- D. 沿用 PHP（可直接复用商派代码，但长期技术债）
- E. 其他 / 需按团队现有能力评估

**影响**：决定重写成本与招聘方向；决定商派 7 个机制（插件链/Lua 规则/Redis 预占/Swoole 队列）用什么等价物实现。

### Q5【P0】财务能力怎么落？数据源是什么？
- A. 对接现有财务系统（用友/金蝶/SAP/其他？请注明），OMS 只做业务单据，凭证推给财务系统
- B. OMS 内自建轻量结算层（应收应付/对账单/核销），再导出给财务
- C. 二者结合：OMS 出业务对账单，财务系统记账（可插拔接口）
- D. MVP 暂不做财务，二期再说

**影响**：决定 finance/financebase/invoice/logisticsaccounts 四个模块（53 张表）是照搬、裁剪还是不做。你此前提过"财务数据源设计为可插拔"，需要确认接口形态与首个对接对象。

### Q6【P0】MVP 上线时间窗与首刀范围？
- 期望上线时间：________（如 2027 Q1）
- 首刀必须打通的链路（勾选）：
  - [ ] 平台拉单 → 审单 → 分仓 → 推仓（通天晓）→ 发货回传
  - [ ] 多货主库存记账与同步
  - [ ] 售后（退货入库 + 退款）
  - [ ] 采购入库
  - [ ] 财务对账
  - [ ] 经销商 B2B 订货

**影响**：决定 6 份逆向文档中哪些先转成详细设计；决定与「OMS 先行过渡期方案-ShopeX 对接通天晓 WMS」的衔接与切换节奏。

### Q7【P0】团队可投入的研发人力？
- 现有可投入人数 / 角色构成（后端、前端、测试、产品）：________
- 是否可招人 / 外包：________

**影响**：决定 MVP 范围能切多小。以商派 113 万行的体量参考，即使压缩 50% 后重写，3 人团队与 10 人团队的可行范围差 3 倍以上。

### Q8【P0】部署与合规要求？
- 部署形态：自建 IDC / 阿里云 / 腾讯云 / 容器化 K8s
- 是否要求与 K-AIDE 平台统一 UI 与设计 token（品牌色 #185FA5）
- 是否要对外门户（品牌方登录查看自己的数据）
- 数据合规：是否有跨境数据、消费者隐私（PIPL）特殊要求

**影响**：决定权限模型是否要多租户对外隔离、是否需要独立前端设计体系、以及商派 pipl.protocol 对应的隐私设计是否要继承。
