## 1. 交付内容

### 1.1 数据模型（`backend/app/models/abnormal.py`）

| 表 | ORM | 说明 |
|---|---|---|
| `ord_abnormal_type_dict` | `OrdAbnormalTypeDict` | 异常类型字典（16 种内置 + OTHER 兜底） |
| `ord_abnormal` | `OrdAbnormal` | 异常单主表（状态机 + 分派 + SLA + 时间线） |
| `ord_stockout` | `OrdStockout` | 缺货明细（三元键 + 缺口量 + 库存快照 + 策略结果） |
| `ord_reason_code_dict` | `OrdReasonCodeDict` | 审单原因码字典（**FR-01c 映射的权威来源**） |

- 全部接入 `registry` 数据权限：异常单 = tenant + owner + shop 三维
- **模型 ↔ DDL 一致性 66/66 通过**（`check_model_ddl.py`）

### 1.2 服务（`backend/app/services/abnormal.py`）

| SRS 条款 | 实现 |
|---|---|
| FR-01a/01b | 内置类型字典读取（类型/分类/默认处理组/默认SLA/动作集/是否落单） |
| FR-01c | 原因码 → 异常类型映射，**权威源 = `ord_reason_code_dict.exc_type`**；未映射 → 兜底「其他异常」 |
| FR-02a | 创建（来源：audit / freeze / push / manual / relink）+ **幂等**（同订单同类型未闭环 → 复用） |
| FR-02b | 状态机：待分派 → 已分派 → 处理中 → 已解决 / 已取消 / 已挂起；非法流转拒绝；时间线留痕 |
| FR-02c | 分派（按类型默认处理组 / 手动改派转派） |
| FR-02d | 动作：开始处理 / 挂起（须填预计恢复时间）/ 解决 / 取消 |
| FR-02e | 闭环联动：解除订单审单原因标记（open → handled）；**多异常单全部闭环才解除** |
| FR-04a | 缺货标记：三元键明细；**同键多次预占失败按缺口量累加合并** |
| FR-04b | 策略链结果回写（`strategy_result`） |
| FR-05a | 超卖标记（`oversold_flag`） |

### 1.3 创建来源接入（FR-03a / FR-03b）

| 来源 | 接入点 | 异常类型 |
|---|---|---|
| 审单不通过 | `audit_engine._raise_abnormals` | 按原因码字典映射 |
| 预占失败 | 走审单阶段 `STOCK_SHORTAGE` 原因码 | `STOCK_SHORT` |
| 预占竞态 | `STOCK_RACE`（`exc_type=NULL`） | **不落单**（回审单池，符合 FR-03a） |
| 推仓失败 | `wms_events` `EVENT_PUSH_FAILED` | `WMS_PUSH_FAILED` |
| WMS 打回 | `wms_events` `EVENT_REJECTED` | `WMS_PUSH_FAILED` |
| 人工标记 | `POST /abnormal` | 指定类型 |

> **落单与否由字典决定，不写死在代码里**：`exc_type` 为空 → 不落单；`need_abnormal_bill=0` → 不落单。
> 落单失败**不阻断**审单主流程与事件编排（try/except + warning 日志）。

### 1.4 API（`backend/app/api/v1/abnormal.py`）

| 端点 | 说明 |
|---|---|
| `GET /abnormal/types` | 类型字典（16 种 + SLA + 动作集） |
| `GET /abnormal/reason-codes` | 原因码字典（32 条，含 exc_type 映射） |
| `GET /abnormal/list` | 列表（类型/状态/分类/订单/店铺/处理组/关键字 + 分页 + SLA） |
| `GET /abnormal/{id}` | 详情（缺货明细 + 时间线 + SLA 剩余小时） |
| `GET /abnormal/stockouts` | 缺货明细列表（FR-04d 看板用） |
| `POST /abnormal` | 人工标记（FR-03d：类型 + 备注必填） |
| `POST /abnormal/{id}/dispatch` | 分派 / 改派 |
| `POST /abnormal/{id}/process` | 开始处理 |
| `POST /abnormal/{id}/suspend` | 挂起（须填预计恢复时间 > 0） |
| `POST /abnormal/{id}/resolve` | 解决（含闭环联动） |
| `POST /abnormal/{id}/cancel` | 取消 |

### 1.5 跨域时间基准统一（复盘遗留项 #1 的一部分）

新增 `backend/app/core/timeutil.py`：`utcnow()` 作为**全域统一 UTC 基准**；
`auth.py` 的 `_utcnow` 收敛为别名。异常单全部时间比较（SLA / 账龄）与 DB 的
`DATETIME` 同基准，与 DB 服务器时区无关。

## 2. 过程中修掉的问题

| # | 问题 | 性质 | 修法 |
|---|---|---|---|
| 1 | 异常单号在 **Redis 不可用时必然重号**（退化成「日期+000000」→ 第二张撞唯一键） | 真实缺陷 | 三级降级：Redis INCR → DB 号段（`bas_seq` CAS）→ UUID 短码 |
| 2 | `ord_reason_code_dict` **无 `is_deleted` 列**，ORM 多写一列必报错 | 真实缺陷 | DDL 校验当场抓到 → 去掉该列 |
| 3 | 我曾按 SRS §5.1 自造异常类型字典 seed，与 **DDL 预置的权威数据不一致**且污染开发库 | 认知偏差 | 删 seed、按 DDL 还原、改为直接用预置数据；动作集命名也按 DDL（`reaudit`/`to_retrial`/`to_aftersale`/`refund`/`force_pass`） |
| 4 | 我以为「不落单」由 `need_abnormal_bill=0` 决定 | 认知偏差 | DDL 里 16 种类型该字段**全为 1** → 实际由 `exc_type` 是否为空决定；测试已按此改写并单独锁住该开关规则 |
