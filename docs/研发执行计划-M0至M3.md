# KT-OMS 研发执行计划（M0-M3 · 3 个月 MVP 内测版）

> 文档编号：PLAN-DEV-01 · 版本 V1.0 · 2026-10-24 · 编写：小凯 · 状态：待 Jason 确认后开工
> 决策输入（2026-10-24 晚确认）：
> - **目标定义**：3 个月完成**三链路 MVP 内测**（正向履约 + 多货主库存 + 售后），内部沙箱/测试店铺验证，**不上生产**
> - **主力开发**：AI（小凯）承担绝大部分编码；Jason + 业务方负责需求确认、评审、验收
> - **首发平台**：天猫/淘宝（gateway 首个适配器；抖音等其余平台后置）
> - **开发环境**：本地 Docker 先行（docker-compose：MySQL8 + Redis7 + RabbitMQ）
> - **技术栈**：Python 3.11+ / FastAPI / SQLAlchemy 2.0 async / Alembic / Pydantic v2 / Vue3 + TS + Element Plus（V2.1 定案）

---

## 1. 范围裁剪（3 个月做什么 / 不做什么）

### 1.1 IN —— 三链路 MVP

| 链路 | 包含模块 | SRS 依据 |
|---|---|---|
| **正向履约** | 淘系拉单（D02.03 轮询+推送）、订单接入（D03.01）、审单引擎（D03.02 核心插件位）、人工审单工作台（D03.03 基础版）、拆单（D03.04 按仓/按货主/按商品类型 3 策略先行，其余 13 策略注册位预留）、配货分仓（D03.06 规则式）、发货单（D03.07 指令状态机）、出库回传（D09.02 通天晓 RESTful）、发货回传平台（D02.04）、异常单（D03.09 缺货/未绑定/地址三类先行） | 批次② SRS |
| **多货主库存** | 物料三层+BOM（D04.01）、三元记账五口径（D04.02）、Redis Lua 预占（D04.03）、出入库单据（D04.04）、可售计算+平台同步（D04.08 共享/比例两策略）、库存对账 | 批次① SRS |
| **售后** | 售后申请单（D05.01 仅退款+退货退款两类，换货/补发接口预留）、退货入库质检良不良分流（D05.02）、退款单台账（D05.03 平台执行只记录） | 批次③ SRS |
| **底座（够用即可）** | 组织/货主/店铺档案（D10.01 基础）、账号+角色+四维数据权限中间件（D10.02/D10.03，**spike 已验证方案**）、MQ outbox（D01.01）、调度器（D01.02 基础）、规则引擎最小版（D01.03 承载审单插件链）、导入导出（D01.06 期初库存/商品导入必需）、PIPL 加密脱敏（D01.05 收货人字段必需） | 批次⑤ SRS |
| **前端** | 审单工作台（键盘流）、订单列表/详情、库存查询、异常单处理、售后单处理、基础档案维护（物料/店铺/仓库）、登录 | — |

### 1.2 OUT —— 明确后置（M3 内测通过后）

合单（D03.05 架构预留开关默认关）· 促销赠品（D03.14）· 特殊单型/即时零售/O2O/跨境（D03.10-12/15）· 客服360视图（D03.16）· 采购全域（D06）· 财务全域（D08，内测期对账用报表导出人工核）· 品牌方门户（D10.04）· OA 审批集成（D10.05，内测期敏感操作=双人复核顶替）· 报表域（D11，留监控看板最小版）· 价格管理（D04.11）· 抖音等 5 平台适配器 · 电子面单（D09.05，内测用测试账号菜鸟面单或跳过实打）· 盘点/调拨/借调/成本核算/批次效期 SN（D04.05-07/09，表已建、服务后置）

> 裁剪原则：**表结构不裁**（373 表 DDL 全量建库，避免后续迁移）；裁的是服务与界面。所有 OUT 项的扩展位（插件注册/策略注册/事件）在 IN 项实现时按 SRS 预留。

## 2. 里程碑倒排（12 周）

```
W1-W2      M0 spike+基建      骨架立起来，三大技术风险清零
W3-W6      M1 库存+拉单       库存域全通 + 天猫订单进得来
W7-W10     M2 审单+履约       审单→拆单→分仓→发货单→通天晓→回传闭环
```

### M0（W1-W2）：技术验证 + 工程基建 —— 出口标准：三份验证报告全绿

| # | 任务 | 产出 | 验收 |
|---|---|---|---|
| 0.1 | docker-compose 基建（MySQL8/Redis7/RabbitMQ + Alembic 迁移 373 表） | `deploy/docker-compose.yml` + 迁移脚本 | 一键起环境，373 表迁移成功 |
| 0.2 | backend/ FastAPI 工程骨架（分层：api/service/domain/infra；配置/日志/异常/中间件规范） | 可运行骨架 + 开发规范文档 | hello 域 CRUD 跑通 |
| 0.3 | frontend/ Vue3+TS+Element Plus 骨架（路由/权限指令/请求封装/OpenAPI 类型生成链） | 可运行骨架 | 登录页+动态菜单 |
| 0.4 | **数据权限过滤验证**（D10.03 风险点①）：SQLAlchemy `with_loader_criteria` + contextvars 四维行级过滤 | 验证报告 | 越权查询拦截用例全过 |
| 0.5 | **Redis Lua 预占原型**（风险点②）：三元键预占/释放/settle 脚本 + 并发压测 | 验证报告 | 200 并发无超卖、幂等键防重 |
| 0.6 | **审单链+吞吐压测**（风险点③）：pluggy/自研责任链最小实现 + 模拟订单流 | 验证报告 | ≥500 单/分钟；Celery vs arq 选型结论 |
| 0.7 | CI（GitHub Actions：lint+pytest+ruff+mypy 门禁） | `.github/workflows/` | PR 自动跑 |

### M1（W3-W6）：库存域 + 平台接入 —— 出口标准：天猫测试店订单自动进 OMS，库存账实一致

- W3：组织/货主/店铺/仓库档案（D10.01/D09.01 最小版）+ 账号角色登录（D10.02）+ 数据权限中间件全局接入
- W3-W4：物料三层+BOM+一品多码（D04.01）+ 导入中心（D01.06：商品/期初库存 Excel 导入）+ 期初建账（D04.04 §5.4）
- W4-W5：**三元记账+五口径**（D04.02 含 5 分钟对账任务）+ **Lua 预占服务化**（D04.03：reserve/release/settle/过期回收）
- W5：Gateway 框架（D02.01 签名/限流/api_log）+ 店铺授权 OAuth（D02.06 淘系）+ **天猫适配器**（D02.02 订单下载/商品查询两能力先行）
- W6：**拉单三保险**（D02.03：轮询水位+单拉补偿先行，TMC 推送视测试账号资质）+ canonical 模型 + 订单缓冲落库（D03.01 接入）+ 未知商品自动建档联动
- W6：可售计算+平台同步（D04.08 两策略）+ MQ outbox 事件底座全通

**M1 演示**：测试店铺下单 → 1 分钟内订单进 OMS → 库存预占 → 可售数回写平台。

### M2（W7-W10）：审单 + 履约闭环 —— 出口标准：订单从拉单到发货回传全自动跑通

- W7：审单引擎（D03.02：插件链框架+核心 8 插件——黑名单/地址/价格基础版/缺货/选仓/拆单/物流匹配/auto_pass；结构化 audit_reason；决策执行分离 plan 落库）
- W7-W8：拆单 3 策略（按仓/按货主/按商品类型）+ 配货分仓规则（D03.06）+ 履约方案执行器
- W8：发货单（D03.07 指令状态机）+ 人工审单工作台前端（D03.03：队列/分派基础版/键盘流/侧滑详情）
- W9：**通天晓 WMS 对接**（D09.01 RESTful 适配器 + D09.02 出库指令下发/回传：运单/包裹/称重→settle 转扣减→order.shipped）⚠️ 外部依赖：需通天晓沙箱账号+接口文档
- W9-W10：发货回传平台（D02.04 back_node=shipped）+ 失败重试（D02.05 api_fail 分级）+ 异常单三类（D03.09：缺货五步策略链/未绑定/地址异常）+ 改地址（D03.08 最小子集：未推仓直改+已推仓叫回）
- W10：订单列表/详情/库存查询前端 + 监控看板最小版（D11.03：拉单水位/审单积压/回传失败三指标）

**M2 演示**：订单自动审单→拆单→分仓→发货单→推通天晓（沙箱）→出库回传→平台发货，全链路无人工干预（正常单）。

### M3（W11-W12）：售后 + 端到端内测 —— 出口标准：三链路内测验收报告

- W11：售后三件套（D05.01 申请单+平台售后消息同步 / D05.02 退货预报→入库质检良不良分流 / D05.03 退款台账）+ 售后工作台前端 + 未发货仅退款→发货拦截联动
- W12：**端到端内测**（真实测试店铺+通天晓沙箱：正向 100 单含拆单/缺货/改地址场景 + 售后 20 单含仅退款/退货退款/质检不良）+ 压测复跑 + 缺陷修复 + **《MVP 内测验收报告》**（含：三链路场景覆盖清单/性能数据/缺陷清单/生产化差距评估——即 M4+ 的输入）
