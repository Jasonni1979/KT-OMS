# KT-OMS 研发执行计划（M0-M3 · 3 个月 MVP 内测版）

> 文档编号：PLAN-DEV-01 · 版本 **V1.1** · 2026-10-25 · 编写：小凯 · 状态：待 Jason 确认
> 决策输入（2026-10-24 晚四项 + 2026-10-25 新增第五项）：
> - **目标定义**：3 个月完成**三链路 MVP 内测**（正向履约 + 多货主库存 + 售后），内部沙箱/仿真环境验证，**不上生产**
> - **主力开发**：AI（小凯）承担绝大部分编码；Jason + 业务方负责需求确认、评审、验收
> - **首发平台**：天猫/淘宝（gateway 首个适配器；抖音等其余平台后置）
> - **开发环境**：本地 Docker 先行（docker-compose：MySQL8 + Redis7 + RabbitMQ）
> - **技术栈**：Python 3.11+ / FastAPI / SQLAlchemy 2.0 async / Alembic / Pydantic v2 / Vue3 + TS + Element Plus（V2.1 定案）
> - **联调解耦（V1.1 新增，2026-10-25 Jason 确认方向）**：天猫测试环境到位时间不确定 → **仿真器先行**：自建天猫平台模拟器（含仿真下单引擎）+ 通天晓 WMS 模拟器，OMS 核心模块全部开发与内测在仿真环境完成；真实平台联调改为并行「联调窗口」，资质/沙箱就绪即插入，**不在关键路径**

## 2. 仿真环境设计（V1.1 新增章）

### 2.1 天猫平台模拟器（mock-platform）

- **形态**：独立 FastAPI 服务，docker-compose 一键起（与 MySQL/Redis/MQ 同栈），代码永久保留仓库 `mocks/platform/`
- **模拟接口**（对齐 D02.02 适配器能力矩阵，淘系）：

| 接口组 | 端点（仿真） | 保真要点 |
|---|---|---|
| 订单增量拉取 | trade.sold.get | created/modified 双水位语义、分页、字段集按 canonical 映射所需 |
| 订单详情 | trade.detail.get | 全量报文（含子订单/优惠明细/买家留言/收货人密文位） |
| 商品查询 | item.get / item.sku.get | 供未知商品自动建档联动（D03.01） |
| 发货回传接收 | logistics.online.send | 记录 OMS 回传请求 → 供链路断言与「平台已发货」状态回放 |
| 售后消息 | refund.get / 售后增量 | 仅退款/退货退款两态报文（D05.01 消费） |

- **保真要求**：TOP 风格签名校验（appkey/secret/session）、统一响应包裹（error_response 结构）、典型错误码（session 过期/限流 isv.trade-service 类/业务错），让适配器的**重试、降级、api_fail 分级逻辑（D02.05）在仿真期就被真实锻炼**
- **配置开关**：适配器 `platform.driver = simulator | taobao`——切真实环境=改一行配置+换凭证，业务模块零感知

### 2.2 仿真下单引擎（造单器）

- **场景库**（对照 SRS 验收标准建矩阵，避免内测盲区）：正常单/多商品单/跨仓拆单触发/缺货触发（联动 D03.09 五步策略）/地址异常/买家留言/未绑定商品/大额单/仅退款/退货退款/质检不良回流……每场景可参数化批量生成
- **触发方式**：手动（前端调试页/API）+ 定时（模拟真实店铺持续出单）+ 批量压测模式
- **一次建设三处复用**：① M1-M2 开发期持续供给测试订单；② W10 端到端内测（正向 100 单/售后 20 单）由批量模式完成；③ CI 每日全链路回归的订单源

### 2.3 通天晓 WMS 模拟器（mock-wms）

- 按 **D09.02 RESTful 契约** mock：出库指令接收（入仓）→ 状态回放（拣货/打包/出库）→ 出库回传（运单号/包裹/称重）→ 拒收/缺货回传场景可配
- `wms.driver = simulator | ttx` 同款开关；**接口文档若拿到**，据实修订 mock 契约（差异收敛在适配器层）
- V1.0 中它是「拿不到沙箱的兜底」，V1.1 **转正为首选**，真实沙箱联调移入联调窗口

### 2.4 联调窗口（并行轨道，不占关键路径）

| 窗口 | 前置条件 | 内容 | 预估 |
|---|---|---|---|
| 淘系真实联调 | 开放平台应用+测试店铺授权就绪（建议 W6 前拿到，晚到不阻塞） | 切 driver=taobao：拉单/回传报文逐字段 diff、签名/限流真实行为验证、TMC 推送（如资质允许） | 0.5-1 周 |
| 通天晓真实联调 | 沙箱账号+接口文档就绪 | 切 driver=ttx：入仓/回传报文 diff、异常场景 | 0.5 周 |

> 联调窗口结论纳入 M3 验收报告的「生产化差距评估」；两窗口都完成 = M4 生产灰度的准入条件之一。
