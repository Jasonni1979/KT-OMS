# 权限豁免调用点清单（D10.03 FR-04d）

> 制度：行级过滤注入是**全域唯一注入点**（`app/core/permission.py` 的 `do_orm_execute` 事件）。
> 系统级任务（MQ worker / 调度 / 平台回传处理 / 跨货主聚合）无用户上下文，
> 必须走**豁免通道** `without_data_scope()`，并在此登记调用点；CI 应静态检查豁免滥用。
> 原则：豁免是例外而非常态——新增豁免点需在 code review 中说明理由。

## 登记清单

| # | 调用点 | 文件:位置 | 豁免理由 | 风险评估 |
|---|---|---|---|---|
| 1 | 跨 schema 演示接口 | `app/api/v1/hello.py:list_tenants` | 系统级只读演示接口，不承载任何用户业务数据 | 低（仅返回租户列表元信息） |
| 2 | 认证链路（登录校验 / 会话校验 / 权限点查询） | `app/services/auth.py`：`login_password` / `validate_access` / `refresh` / `permissions_of` / `_is_superuser` / `_audit_fail` | 发生在 AuthContext 注入**之前**（先有鸡还是先有蛋的必然约束） | 低（查询范围=本账户自身记录） |
| 3 | 权限 scope 解析（四步模型） | `app/services/permission.py`：`get_scope` / `_compute` / `_expand_nodes` | 同上——scope 解析是 AuthContext 的来源，不能被自己过滤 | 低（解析目标=授权关系表） |
| 4 | 超管 bypass | `app/core/permission.py:_build_criteria`（`ctx.is_superuser` / `ctx.all_data`） | 内部超管与 `all` 模式角色（SRS §5.1 第①步） | 中（依赖角色授权正确性，由 D10.02 角色管理约束） |

## 明确禁止的豁免场景

- 业务域列表/详情接口（应走 scope 过滤）
- 写操作前置校验（`assertWritable`，SRS §5.3）——写路径必须校验，不得豁免
- 报表/导出（D08 结算、D11 报表）——应使用豁免 + **系统角色**，且输出结果按消费方权限二次过滤
- 品牌方门户（D10.04）——外部租户硬隔离不可配置放宽（FR-06b）

## CI 检查建议（待 M1b 落地）

```bash
# 静态扫描：业务域代码中不应出现 without_data_scope / system_scope
rg -n "without_data_scope|system_scope" app/services app/api --glob '!app/services/auth.py' --glob '!app/services/permission.py'
# 命中即需人工确认（豁免点登记表与代码一致性检查）
```
