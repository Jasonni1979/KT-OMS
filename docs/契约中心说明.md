## 一、为什么建（这是「底层错误」的头号根因）

过去枚举值与中文标签**散落在 39 个 service 里各抄一份**，DDL 变更时必然漂移。

W9 三轮整体检查实测到的真实缺陷，根因全部是枚举漂移：

| 缺陷 | 表现 |
|---|---|
| 换货状态机缺边 | `aftersale.py` 的流转表缺「待审核 → 换货执行中」→ 换货审核必然报「不可流转」 |
| 应急批次阶段表缺边 | `abnormal_ext.py` 的阶段表与 SRS 不一致 → 阶段推进失败 |
| 改单类型枚举对不上 | `modify.py` 手抄 `item`/`memo`，DDL 是 `item_add`/`item_sub`/`item_swap`/`remark` → **P0 门禁首次运行即抓出** |

**这类 bug 靠人眼发现不了，且发现时已晚一个批次。**

## 三、生成流程（为什么从「DDL 文件」而不是「数据库」）

```
docs/database/sql/DB-*.sql   ← 权威源（UTF-8 文本）
        │  tools/gen_contracts.py
        ▼
backend/app/contracts/enums.py  ← 自动生成
```

### ⚠ 为什么不用 information_schema

开发库的 DDL 注释是**双重编码且部分不可逆损坏**的 —— 导入时字符集处理不当，
`utf8mb3 → utf8mb4` 转换把字节 `0x94` 替换成了 `U+201D`：

```
"主键" 正确 UTF-8 = E4 B8 BB E9 94 AE
库里存的字节      = C3 A4 C2 B8 C2 BB C3 A9 E2 80 9D C2 AE   ← 0x94 已被替换，不可还原
```

从库里读出来的是坏数据，**且无法还原**。DDL SQL 文件本身是 UTF-8 源文件 —— 才是权威源。

**附带好处**：生成不依赖数据库 → 本地与 CI 结果完全一致、门禁零外部依赖。

### 解析器覆盖的 DDL 注释格式

| 格式 | 示例 | 产出 |
|---|---|---|
| 数值枚举 | `1=待退款,2=退款中(平台受理打款)` | `{1: '待退款', 2: '退款中'}` |
| 字符串枚举 + 中文 | `alarm告警/alloc_calc调拨测算` | `{'alarm': '告警', ...}` |
| 字符串枚举纯 code | `create/update/delete/...` | `{'create': 'create', ...}` |

**坑位记录**（都踩过）：中文冒号「：」≠ ASCII「:」· ASCII 与全角括号混用 ·
code 可能全大写（`RETRYABLE`）· 括号内的补充说明不是枚举值 · `_ref`/`_id` 结尾的多是引用路径不是枚举。

## 四、门禁（`tools/check_contract_ddl.py`，已入 CI）

| 检查 | 内容 | 当前结果 |
|---|---|---|
| **C1** | `enums.py` 与 DDL 同步（重新生成无 diff） | ✓ 771 列 |
| **C2** | 代码里的手抄枚举映射表 ↔ DDL 枚举列：**漂移即失败** | ✓ 0 漂移 |
| **C2-b** | 兜底：代码用的枚举值若不在任何 DDL 枚举里 → 失败 | ✓ 0 |
| **C3** | 裸常量取值必须落在 DDL 枚举集合内（warning） | ✓ 2 条 warning |
| **C4** | 状态机流转表的状态值必须在 DDL 枚举内 | ✓ 0 非法引用 |

**匹配原理**：中文标签是 DDL 与代码之间的天然公共键 ——
代码里 `ST_WAIT_AUDIT = 1` + `APPLY_STATUS_LABEL = {ST_WAIT_AUDIT: "待审核"}`
拼出的 `{1: "待审核"}`，与 DDL 的标签集求交即可定位对应列。

**误报处理**（已实测并收敛）：
- 值是英文标识符的表（错误码→分级、Redis 字段→DB 字段）→ 不参与比对
- 键集相似度 < 0.6 → 不算同一枚举
- 白名单：`_ERROR_CODE_DESC`（错误码描述表）

## 六、使用方式

```python
from app.contracts.enums import AFT_RETURN_APPLY_STATUS, ORD_RISK_LIST_LIST_TYPE

# 值 → 中文标签
AFT_RETURN_APPLY_STATUS[1]            # '待审核'
ORD_RISK_LIST_LIST_TYPE["black"]       # '黑名单'

# 反查（标签写错会立刻 KeyError，而不是静默取到错误状态码）
from app.contracts.enums import ENUM_BY_LABEL
ENUM_BY_LABEL["oms_aftersale.aft_return_apply.status"]["待审核"]   # 1
```

```bash
# 重新生成（DDL 变更后必跑）
cd backend && .venv/bin/python ../tools/gen_contracts.py

# 门禁校验
cd backend && .venv/bin/python ../tools/check_contract_ddl.py
```
