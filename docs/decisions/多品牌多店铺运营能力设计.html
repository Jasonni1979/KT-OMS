多品牌多店铺运营能力设计

隔离设计的另一半：从「数据不串」到「多品牌日常可运营」· 租户模型 / 接入产品化 / 角色作业台 / 跨品牌视图
版本 V1.02026-10-23 配套：《底座复核与多品牌隔离设计》V1.0 规模基线：现状 ≤10 品牌/≤100 店铺 · 目标容量 30 品牌/500 店铺/日均 5 万单
本报告的定位 隔离设计回答了「品牌之间数据不串、货权不混」——那是防守面。 代运营商的多品牌多店铺还有进攻面：签一个新品牌=一个新租户上线，接入速度就是营收速度； 运营团队要按品牌高效作业（混合制：大品牌专团队+小品牌共享池）；管理层要跨品牌看经营。 本报告设计四件事：租户模型、品牌接入产品化（≤3 工作日/品牌）、角色模板与品牌作业台、跨品牌经营视图。
规模结论先行 现状 ≤10 品牌/≤100 店铺，单逻辑实例承载毫无压力；按 30 品牌/500 店铺/日均 5 万单 做目标容量设计（约 3 年余量）， 底座订单表已有 idx_shopid_orderid_createtime、idx_orgid_ordertype... 复合索引，同步任务按店铺分片即可覆盖目标容量——规模不构成架构风险，接入效率才是代运营的真瓶颈。

01租户模型：品牌=租户

图 1 · 租户模型：品牌=租户，挂载店铺/策略/角色/商品库存/结算五类资源；跨品牌层只读聚合；生命周期含路由、退出与迁移通道

1.1 租户标识的三重映射（与底座字段对齐）

概念底座承载职责边界
品牌（租户）租户主表（新建）= 品牌档案商务与生命周期主体：合同、路由判定、退出归档
核算主体organization.cos（cos_id）财务与结算维度：结算单/对账单强制携带
货主库存 owner 字段（隔离设计组件②新建，语义复用 cos）库存与仓内作业维度：WMS 货主档案一一对应
组织节点organization.org（org_id）运营组织维度：角色挂载与作业台分组

四个 ID 在租户主表中一一映射并作为唯一权威，任何业务表只引用其中之一（按维度选），禁止业务代码自行推断映射关系——这是防止「品牌-店铺-货主」错挂的制度性保障。

02品牌接入产品化（五步 SOP，目标 ≤3 工作日/品牌）

步动作内容耗时目标
1品牌建档租户主表创建；cos/org/owner 三 ID 生成并映射；路由判定结论挂档（逻辑/物理）0.5 天（含双签）
2店铺接入店铺创建+平台授权（Token）；店铺-货主映射配置；授权连通性自动校验0.5-1 天（视平台审核）
3模板套用从模板库选择并实例化：审单规则模板、库存同步策略模板、结算口径模板、售后策略模板；差异项逐条确认0.5 天
4角色分配按运营模式选角色模板（专团队/共享池）实例化；账号开通与店铺集合授权0.5 天
5验证放行接入自检清单自动跑：授权拉单 1 笔、审单规则命中校验、库存同步值比对、权限越权抽测 4 项；全绿后租户置「运营中」0.5 天

2.1 模板库设计（接入速度的核心资产）

  • 四类模板：审单规则、库存同步策略（可售计算/安全库存/同步频率）、结算口径（佣金结构/费用项/对账维度）、售后策略（退货地址/仅退款阈值/换货规则）。
  • 版本化+继承：模板有版本号，品牌实例化时记录模板版本；模板升级不自动覆盖已实例化品牌，提供「差异对比+选择性升级」。
  • 模板来源：首批模板从存量品牌配置反向提炼（M1 知识抢救回访纪要+通天晓 OFS 配置导出）；此后每接入 3 个品牌复盘一次模板覆盖率，覆盖率目标 ≥80%（即 80% 配置项无需品牌级定制）。
接入 SOP 的验收方式：真品牌演练 试点阶段（S2）内，用一个真实新签品牌按五步 SOP 完成接入并纳入 G2 门禁验收——证明接入是产品化能力而非人工手艺。 若当期无新签品牌，则用一个存量品牌做「退出-重接入」演练（在测试实例执行）。

03角色模板与品牌作业台

3.1 角色模板（混合制运营的两套基线）

角色模板数据范围（行级权限中间件注入）典型作业
品牌运营（专团队）本品牌全部店铺：订单/库存/售后读写；本品牌结算只读审单、异常单处理、库存策略调整、售后处理
共享池运营被授权的 N 个品牌店铺集合（账号级配置）；品牌间切换作业同品牌运营，多品牌轮转；作业台带品牌切换器
品牌客服本品牌订单/售后读写；库存只读；结算不可见查单、退货登记、物流异常跟进
品牌财务对接人本品牌结算/对账读写；订单只读（金额字段可见）对账单确认、费用核对、发票信息维护
运营总监（跨品牌）全部逻辑实例品牌的订单/库存只读+聚合；物理实例仅聚合值跨品牌巡检、资源调配、升级决策
系统管理员配置权限全开，业务数据默认不可见（需临时授权+审计留痕）模板维护、租户管理、权限配置

设计原则：角色模板=功能权限包，账号=角色模板×店铺集合（数据范围）的实例化。功能权限与数据范围正交分离——这是隔离设计组件①在运营侧的落地形态，避免为每个品牌×角色组合硬编码权限。

3.2 品牌作业台（日常运营的统一入口）

  • 品牌切换器：共享池运营登录后默认进入「我的品牌」列表，切换品牌即切换全部页面数据范围（中间件按当前品牌注入过滤）；切换动作记审计。
  • 作业台四象限：待审单/异常单（履约）、库存预警（可售低于安全线/同步失败）、售后待办、对账待确认——每象限只展示当前品牌数据并带平台维度细分。
  • 大促模式：品牌级开关，开启后作业台突出积压监控与批量审单入口，冻结该品牌策略变更（与迁移方案冻结窗口联动）。

04跨品牌经营视图

视图内容数据源与权限
经营看板各品牌 GMV/单量/履约时效/客诉率/库存周转，日粒度趋势逻辑实例聚合表（T+1）+ 物理实例上送聚合值；运营总监/管理层可见
品牌对比报表同指标跨品牌横向对比、排名、环比同上；导出带水印与授权记录
接入与续约视图租户生命周期状态、合同到期提醒、接入 SOP 进度租户主表；商务+管理层可见
资源负载视图各品牌同步任务量/接口调用量/异常率，用于共享池排班与容量规划监控组件；技术负责人+运营总监可见

边界规则：跨品牌视图只读、聚合、脱敏三原则；明细数据永不跨品牌可见（含管理层）；物理隔离品牌在视图中与逻辑品牌呈现一致（聚合值同构），管理层无感知差异。视图实现为独立聚合服务（T+1 批处理），不侵入 OMS 在线库——与建议书「KPI 报表独立服务」的 P2 规划同源，MVP 期先交付经营看板最小集（单量/GMV/履约时效三指标）。

05规模与性能设计

维度目标容量（3 年余量）设计对策
订单量日均 5 万单、大促峰值 10 倍底座 Swoole 队列+订单表复合索引（idx_shopid_orderid_createtime 已存在）；归档策略：完结订单 90 天后转归档分区（与只读历史库同构）
店铺同步500 店铺并发拉单/回传同步任务按店铺分片+令牌桶限流（按平台配额）；失败店铺自动退避重试并告警
权限模型千级账号×店铺集合授权账号→店铺集合授权结果缓存（变更即失效）；中间件过滤走索引字段，不引入全表扫描
库存货主×仓×SKU 千万级行五态库存按（owner, warehouse, sku）主键组织；可售计算批处理+增量触发双通道
实例数逻辑 1 + 物理 ≤3物理实例超 3 触发架构复盘（隔离设计 5 章）；逻辑实例垂直扩容优先于拆分
规模结论 现状到目标容量之间有 5 倍以上余量，且底座索引与队列模型已覆盖主要压力点——多品牌规模不是本项目的架构风险项。 真正需要持续投入的是接入效率（模板覆盖率）与权限模型的正确性（渗透测试），两者都已挂门禁。

06里程碑影响与验收

阶段本报告新增交付验收标准
M1租户主表与四 ID 映射设计定稿；模板库首批模板提炼（来源：知识抢救纪要+OFS 配置导出）映射表评审通过；四类模板各 ≥1 个基线版本
M2角色模板六类实现+品牌作业台（切换器/四象限/大促模式）；接入 SOP 工具化（自检清单自动跑）越权抽测全绿；作业台 UAT 通过（运营代表签字）
S2（试点）真实新品牌按五步 SOP 接入演练（或存量品牌退出-重接入演练）接入耗时 ≤3 工作日；自检清单全绿；纳入 G2 门禁
M4-M6跨品牌经营看板最小集上线；模板覆盖率复盘机制启动看板三指标与财务口径勾稽一致；覆盖率基线建立
收尾：代运营视角的完整能力图 隔离设计（防守面）+ 本报告（进攻面）= 多品牌多店铺的完整答案： 数据不串（强制层四组件+混合隔离）、接得快（五步 SOP+模板库，≤3 工作日/品牌）、 作业顺（角色模板×数据范围正交+品牌作业台）、看得清（跨品牌只读聚合视图）、撑得住（目标容量 3 年余量）。 五项能力分别挂 G1/G2 门禁与 M1/M2 交付物，随主计划推进，不另立项目。
