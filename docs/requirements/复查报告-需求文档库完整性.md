## 三、发现的能力缺口（5 处，电商代运营专业角度）

> 分级：🔴 建议补（代运营高频刚需）· 🟡 视业务定 · ⚪ 边界外可不做

### 🔴 缺口 1：促销赠品「自动加赠引擎」（满赠/买赠/满件折） ✅ 已补（V1.1：新增 SRS-D03.14 + 促销 5 表，MySQL8 实测通过）
- **现状**：D03.02 审单插件链第 14 位 `gift_check` 只做**校验平台已带赠品**（tbgift/crm 赠品匹配与库存联动），D03.04 有「按赠品拆分」策略，D04.01 有赠品物料类型——但**没有 OMS 主动的促销规则引擎**：即"店铺配置满 299 送面膜小样，审单时自动往订单插入赠品行"。
- **商派对照**：商派有独立 `ome.gift_rule`（赠品规则）+ `gift_logs`/`gift_set_logs`（加赠日志）+ `crm.gift_rule_base`，是完整的促销加赠能力。
- **影响**：美妆/日化代运营（娇韵诗等）**满赠是最高频促销手段**，缺此能力则赠品只能靠平台侧配置或人工加，大促期间工作量巨大且易错。
- **建议**：新增 **D03.14 促销与赠品引擎**（P1，M3），或在 D03.02 审单插件链中增加「促销加赠」插件段（选仓前执行）。规则模型：条件（金额/件数/指定SKU/活动时间/店铺）→ 动作（加赠品行/满减/折扣）。

### 🔴 缺口 2：淘客/分销订单与佣金 ✅ 已补（V1.1：D03.01 推广来源字段组+FR-04g，D08.01 FR-06e 佣金归因）
- **现状**：全库**零覆盖**（grep 淘客/分销单/fxw = 0）。
- **商派对照**：商派有 `ome.fxw_orders`（分销王订单）+ `tbfx_orders/tbfx_order_items/tbfx_order_objects`（淘宝分销）4 张表。
- **影响**：若凯淳代运营品牌有淘宝客/京东联盟/抖音精选联盟推广，这类订单需标记推广来源、计算佣金、佣金影响结算净额（D08.02）。
- **建议**：**取决于业务**——见待确认问题。若需要，作为订单来源类型之一（D03.01）+ 佣金字段（D08.01 平台扣费项已可承载佣金，仅需补推广来源标记）。

### 🟡 缺口 3：消费者 C 端短信/通知触达 ✅ 已定案（不补，走平台消息；已写入 README §8 边界声明）
- **现状**：D01.07 通知中心是**内部告警**（企微/运维），C 端触达仅有 D03.11 门店自提码短信；**没有常规的"订单已发货/物流到达"消费者短信**。
- **行业实践**：多数走**平台官方消息**（淘宝/抖音站内信，平台强制且免费），OMS 自建短信成本高且到达率不如平台。
- **建议**：优先级低。若运营确需短信（如私域/微信小店无平台消息通道），在 D01.07 扩展"C 端触达通道"+ 模板即可，非独立模块。

### ⚪ 缺口 4：评价管理/中差评分 ✅ 已定案（归 CRM；已写入 README §8 边界声明）
- **现状**：零覆盖。
- **判断**：评价管理属于**客服/CRM/舆情系统**职责（凯淳已有 RB-Monitor 舆情日报、CRM 会员系统），OMS 不做评价是**合理边界**。
- **建议**：不补，仅在 README 边界说明中显式声明"评价管理归 CRM/客服系统"。

### ⚪ 缺口 5：会员积分/会员等级运营 ✅ 已定案（积分归 CRM，OMS 只存基础档案；已写入 README §8 边界声明）
- **现状**：会员/客户等级仅 D03.10/D05.05 各 1-3 处（作为审单/售后规则维度），无积分体系。
- **判断**：Q28 已定"客户主数据 OMS 自建"，但**会员运营（积分/成长值/权益）属于 CRM 职责**，OMS 只需会员基础档案（等级作为规则维度）。当前设计合理。
- **建议**：不补积分；确认 OMS members 档案与 CRM 的同步边界（见待确认）。

## 六、复查总评与建议

**总体判断**：需求文档库**主干完整、契约严谨、数据层可落地**，达到"可进入详细设计与 M0 开发"的成熟度。5 处缺口中：
- **1 处建议补**（促销赠品引擎，代运营刚需）
- **1 处取决于业务**（淘客分销）
- **1 处优先级低**（C端短信）
- **2 处建议明确划为边界外**（评价、积分归 CRM）

**建议动作**：
1. 就下方 4 个问题请你拍板（是否补促销赠品引擎、淘客分销业务有无、C端短信、CRM边界）；

3. 无争议项（评价/积分/WMS作业等边界）直接在 README 补一节"系统边界声明"，避免后续误解。
