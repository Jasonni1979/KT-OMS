## A. 入驻准备期（新品牌接手第 1-2 周）

### SC-A01 品牌签约与店铺接入
**业务**：凯淳与品牌方签署代运营合同（约定服务费模式：销售额比例/固定/阶梯），品牌方提供天猫店铺账号。项目组在凯淳侧立项。
**操作**：运营总监在 OMS 建立货主档案（品牌代销类型）→ 挂接组织树（集团→品牌→货主公司）→ 配置结算周期与服务费规则。
**系统支撑**：D10.01 组织架构与货主管理（货主类型=品牌代销、合同关联、结算周期配置）；D08.02 服务费佣金模型（比例/固定/阶梯，基数口径可配）。
**验证**：✅ 货主档案→组织树→结算配置链路完整；多品牌隔离从建档起就生效（owner_id 贯穿）。

### SC-A02 店铺授权
**业务**：店铺账号交接后，OMS 需获得平台 API 授权才能拉单/回传。天猫走 OAuth（子账号授权或主账号授权）。
**操作**：运营在「店铺授权」页选择平台=天猫 → 构建授权 URL → 品牌方登录确认 → 回调落 token → 授权状态=正常。
**系统支撑**：D02.06 店铺授权管理（OAuth 流程/token 加密存储/有效期监控/自动续期/过期告警与重新授权引导）；店铺档案关联货主/租户/组织。
**验证**：✅ 完整；授权过期是代运营高频事故点（过期=停止拉单=漏单），D02.06 的到期监控+D01.07 告警覆盖。

### SC-A03 仓库与物流配置
**业务**：确认该品牌货放哪个仓（凯淳租用的通天晓管理仓/品牌方仓）、用哪些快递（品牌指定或凯淳协议价）、退货到哪。
**操作**：配置仓库档案与 WMS 绑定（通天晓 RESTful/奇门）→ 店铺绑定可用仓与物流商 → 配置区域路由规则 → 配置退货地址（按货主）。
**系统支撑**：D09.01 仓库与多WMS路由；D09.04 物流公司与分单路由（区域路由/运费模板）；D05.02 退货地址按货主配置+店铺覆盖。
**验证**：✅ 完整；品牌方指定仓（不自提）场景=货主×仓关联（D10.01），串货防控在盘点串货识别（D04.06）。

### SC-A04 商品主档建立
**业务**：品牌方给一份商品清单（货号/条码/规格/成本/售价）。买断货凯淳采购入仓；代销货品牌方铺货或直送仓。
**操作**：批量导入基础物料（Excel）→ 一品多码登记（厂商码/店铺码/WMS码）→ 金蝶物料编码映射 → 组合装建 BOM（礼盒=单品×N+包材）。
**系统支撑**：D04.01 商品与物料管理（三层模型：基础物料/销售物料/BOM 绑定；导入经 D01.06；一品多码 inv_barcode；kingdee_material_code 映射）。
**验证**：✅ 完整；同货主 BOM 校验（禁止跨货主组合，礼盒+赠品跨货主走订单层组合）。

### SC-A05 期初库存建账
**业务**：接手时仓里已有货（品牌方铺货或前 TP 遗留），需要把账建起来：仓×SKU×货主三元期初，含批次效期（美妆/酒水必录）。
**操作**：仓库实盘（或信任通天晓现账面）→ OMS 导入期初（Excel：仓/货号/货主/数量/批次/效期/成本）→ 生成期初建账单据 → 库存五口径生效。
**系统支撑**：D04.04 §5.4 期初迁移专用通道（期初建账单据类型，五口径拆分导入）；D04.09 批次效期录入；D04.07 成本初始化（买断=采购成本，代销=代管货值登记）。
**验证**：✅ 完整；期初与通天晓账面对不上时走盘点差异流程（D04.06）。

### SC-A06 历史数据与平台商品同步
**业务**：老店铺有历史订单（售后要用）；平台在售商品要同步进来建立映射。
**操作**：历史订单按迁移通道导入（近 3 年入归档库）；平台商品拉取→自动建销售物料（未绑定态）→商品专员绑定基础物料。
**系统支撑**：D03.13 归档（M4 迁移直接入归档库）；D04.01 拉单自动建档+待绑定清单+绑定后异常订单自动重解析。
**验证**：✅ 完整。

## B. 商品与库存初始化（第 2-3 周）

### SC-B01 平台商品映射
**业务**：天猫店铺 200 个 SKU 链接（含规格色号），每个链接对应仓内一个或多个货号。
**操作**：销售物料（店铺维度）↔基础物料（货主维度）绑定；套装链接绑 BOM；映射错误会导致拉单商品无法解析（进异常单）。
**系统支撑**：D04.01（bind_status/待绑定清单）；D03.09 异常类型 UNBOUND_SKU（商品未绑定→商品组处理→重审）。
**验证**：✅ 完整；自动建档模式（Jason 决策）下新链接上架当天订单就能进来，绑定完成前订单挂异常不丢。

### SC-B02 可售库存首次同步
**业务**：期初建账后，把可售数同步到天猫（品牌方约定该店放 80% 库存，留 20% 给线下/其他渠道）。
**操作**：配置店铺同步策略（shared_ratio 80%）→ 触发全量回写 → 平台前台库存生效。
**系统支撑**：D04.08 可售计算与平台同步（四种策略：独立/比例/全量-安全库存/活动锁定；计算链：available→借调→BOM展开→策略换算→上下限修正）。
**验证**：✅ 完整；库存变更 ≤10 秒回写（Q37 大促可扛级）。

### SC-B03 采购入仓（买断货）
**业务**：凯淳买断的货品向品牌方下采购单，货到仓验收上架。
**操作**：补货建议（销量预测）→采购申请→OA 审批→采购单→到货→WMS 收货质检回传→入库记账→暂估成本→发票到价差回冲。
**系统支撑**：D04.10→D06.01→D10.05(OA)→D06.02→D06.03→D09.03→D04.04→D04.07 全链路。
**验证**：✅ 完整；代销货补货=预警推品牌方门户（D04.10 SC-03，凯淳不采购）。

### SC-B04 组合装与赠品配置
**业务**：美妆大促前配置「买正装送小样」满赠活动；家清配置「洗衣液 2 瓶+柔顺剂 1 瓶」组合装链接。
**操作**：组合装=BOM 绑定（销售物料→基础物料×N）；满赠=促销活动配置（条件：满 299/指定 SKU；动作：送小样 A，阶梯满 599 加送 B）。
**系统支撑**：D04.01 BOM；D03.14 促销与赠品引擎（满赠/买赠/阶梯/互斥裁决/赠品缺货策略）。
**验证**：✅ 完整（V1.1 增补）；赠品也预占库存、也拆单（gift_separate 策略）。

### SC-B05 店铺上线检查
**业务**：正式接单前 checklist：授权正常？物流配置完？测试单跑通？库存同步对？
**操作**：手工建测试单→全流程走一遍（审单→推仓→WMS 出库回传→发货回传平台）→核对。
**系统支撑**：D03.01 手工建单（L 单）；D11.03 监控看板（授权状态/拉单水位/回传成功率全绿）。
**验证**：✅ 完整；建议 M1 验收用例即按此场景编排。

## C. 日常订单履约（每天）

### SC-C01 订单拉取
**业务**：买家下单付款，订单 1 分钟内进 OMS（天猫双 11 峰值每分钟数千单）。
**链路**：平台消息推送（TMC）→ gw_msg_notify 缓冲 → 幂等消费 → canonical 标准模型 → order_buffer 落库 → 合单指纹聚组（缓冲窗）→ 投审单池；轮询水位兜底 + 单拉补偿（三保险）。
**系统支撑**：D02.03/D02.01；D03.01 接入创建（四套状态初始化/双口径金额分摊/BOM 快照固化）。
**验证**：✅ 完整；未知商品自动建档不阻塞其他订单。

### SC-C02 自动审单
**业务**：80%+ 订单无人工干预直通：校验（黑名单/地址/价格/留言关键词/限购）→选仓→拆合单→选物流→预占→生成发货单→推仓。
**链路**：审单插件链 20 位（五段：风控→拦截→校验→决策→裁决）；决策与执行分离（履约方案 plan 落库→执行器统一生成发货单）；预占 Saga（部分失败补偿释放）。
**系统支撑**：D03.02 审单引擎（吞吐 ≥500 单/分钟）；D03.04 拆单 16 策略；D03.05 合单指纹；D03.06 分仓；D04.03 Redis+Lua 预占。
**验证**：✅ 完整；红旗订单强制 HOLD（V1.4 协同标记联动）。

### SC-C03 人工审单
**业务**：地址不全、价格异常、命中限购、缺货等订单转人工；审单组按店铺/品牌分工。
**操作**：多维分派→审核员工作台（键盘流：J/K 移动、P 通过、R 驳回、1-5 标旗）→侧滑详情（含买家留言/历史订单/风险提示）→通过或驳回（原因必填）。
**系统支撑**：D03.03 人工审单工作台（分派规则/负载均衡/绩效）+ V1.4 FR-09 协同标记操作。
**验证**：✅ 完整；催单单据队列提权+48h 红色告警。

### SC-C04 发货与回传
**业务**：仓内拣货打包出库（通天晓作业），OMS 收出库回传→预占转扣减→平台发货回传→买家看到运单号。
**链路**：出库指令（携面单信息）→WMS 回传（运单/包裹/称重/批次/SN）→FreezeService::settle→ord_delivery 状态推进→order.shipped 事件→D02.04 平台回传（back_node 三档时机）。
**系统支撑**：D03.07 发货单指令状态机；D09.02 出库指令与回传；D09.05 面单取号（OMS 取号+仓内打印）。
**验证**：✅ 完整；回传失败进 api_fail 分级重试，5 分钟积压告警（平台考核发货时效）。

### SC-C05 买家催发货
**业务**：付款 48 小时未发货，买家在旺旺催/平台催发货消息进来。
**链路**：平台催发货消息（D02.03 识别）或客服代标 → OrderMarkService::setUrge → 审单队列提权+推仓加急标记 → 发货后自动消标；临近平台承诺时效 48h 未发→红色告警（延迟发货赔付风险）。
**系统支撑**：D03.01 FR-04h（V1.4）+D03.03 FR-09b+D11.03 催单时效看板。
**验证**：✅ V1.4 补全（此前缺口）。

### SC-C06 客服改地址/改单
**业务**：买家付款后发现地址写错，旺旺联系客服改地址；或要加一件商品。
**链路**：客服 360 视图查单→改地址（未推仓：直接改+快照；已推仓：先叫回发货单→改→重推）；加购=改商品行（BOM 重展开+补预占）；改价超权限走 OA 审批。
**系统支撑**：D03.08 订单修改与复审（快照/冻结/差异对比/回滚）；D03.07 叫回指令；D03.16 客服视图入口（V1.4）。
**验证**：✅ 完整；平台侧买家自助改地址消息也经 D02 同步应用。

### SC-C07 订单旗帜协同
**业务**：VIP 大客户订单标紫旗优先处理；有纠纷风险的标红旗停发；天猫运营在千牛标旗，OMS 审单员要能看到。
**链路**：平台旗帜（seller_flag 1-5）拉单解析落 flag_color；OMS 侧标旗→回传平台（支持的平台）；双向变更留痕（ord_flag_change_log）；红旗=审单强制 HOLD。
**系统支撑**：D03.01 FR-04h+D02.04 FR-09 旗帜双向同步（V1.4）。
**验证**：✅ V1.4 补全（此前缺口——天猫运营与 OMS 审单的核心协同语言）。

### SC-C08 缺货与超卖应急
**业务**：大促后部分订单缺货（可售同步延迟导致平台超卖成交）。
**链路**：预占失败→缺货标记→策略链（换仓重试→借调建议→采购加急→与买家协商：等待/退款/换货）→超卖分级处置（4h 内调拨解决/24h 协商/超时赔付登记）。
**系统支撑**：D03.09 异常单与缺货处理；D04.05 借调（P1）；赔付走 D05.01 补发/退款。
**验证**：✅ 完整；超卖是代运营赔付高风险点，处置时效看板（D11.03）盯防。

### SC-C09 订单归档
**业务**：完结 6 个月以上订单转归档库，在线库瘦身；客服仍可查。
**系统支撑**：D03.13（冷热分离/售后期内不归档/摘要行检索/回捞机制）。
**验证**：✅ 完整。

## D. 客服与售后（每天）

### SC-D01 买家咨询「货到哪了」
**业务**：客服在千牛接咨询，需要秒查订单全貌：什么状态、哪个仓发的、什么快递、到哪了、有无售后记录。
**操作**：客服打开 OMS 360 视图→输订单号/手机号→单页聚合（四套状态时间轴/物流轨迹/商品行/金额/售后史/旗帜备注）→回复买家。
**系统支撑**：D03.16 客服订单360视图（V1.4 新增：多维检索/多源并发聚合 ≤1s/PIPL 脱敏/操作入口跳转）。
**验证**：✅ V1.4 补全（此前查单能力分散三处）。

### SC-D02 未发货仅退款
**业务**：买家付款后反悔，未发货秒退。平台退款消息进来，货还没出库要拦住。
**链路**：platform.aftersale.created→aft_return_apply（仅退款）→aftersale.refundonly.unshipped 高优事件→D03.09 发货拦截/叫回→释放预占→平台退款状态同步（OMS 只记录）→退款台账。
**系统支撑**：D05.01/D05.03/D03.07 叫回/D04.03 释放。
**验证**：✅ 完整；拦截窗口期竞争（正在推仓）走叫回失败人工跟进。

### SC-D03 退货退款（七天无理由）
**业务**：买家签收 3 天申请无理由退货。小额自动同意；退货寄回、仓库质检、退款。
**链路**：申请单（自动审核规则：时效内+原因白名单+金额≤阈值→自动同意）→退货预报（地址按货主路由）→买家寄回→WMS 质检回传（良品入实际/不良入次品；SN 属单校验防调包）→良品入库触发退款→平台打款状态同步→应收冲减（按原分摊比例回冲）。
**系统支撑**：D05.01→D05.05→D05.02→D09.03→D04.04→D05.03→D08.01。
**验证**：✅ 完整；美妆拆封不退场景=原因白名单排除+类目强制人工（goods_check 插件）。

### SC-D04 高值退货（奢品箱包珠宝）
