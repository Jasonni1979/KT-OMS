## 2. 关键机制

### 2.1 指令下发（FR-01a ~ FR-01d）

```
DeliveryService.push(draft → pushed)
  └─ OutboundCommandService.push(delivery_ids, push_round)
       ├─ WmsRouteService.route(branch_id, owner_id, "OUT")   ← D09.01 四元组
       ├─ 幂等校验：idempotent_key = delivery_id + 推送轮次
       ├─ 指令组装：发货单 → 标准 DTO（SKU 编码 / 数量 / 货主）
       ├─ 适配器映射：ttx_rest 报文 或 qimen 报文（+ 签名）
       ├─ HTTP 下发 → WMS 受理应答（回填 wms_bill_no）
       ├─ 指令落库 ful_outbound_cmd（状态 = sent）
       ├─ 通道日志 ful_channel_log（方向/动作/耗时/错误码）
       └─ 失败登记 ful_cmd_fail（RETRYABLE 退避重试 / FATAL 终态）
```

**受理即返回**：下发结果异步通过 `wms.outbound.pushed` 事件回推 D03.07 置 `pushed` 态。

### 2.2 回传接收（FR-03a ~ FR-03f）

五步：解析标准化 → 幂等校验 → 指令匹配回填 → 回传登记 → 应答回执（事件异步）。

| 步骤 | 实现要点 |
|---|---|
| 解析标准化 | WMS 用**物料编码**回传 → 通道层映射为 OMS `bm_id`（编排层只认 bm_id） |
| 幂等校验 | 幂等键 = `发货单号:批次号:回传类型`，重复投递返回 `duplicated=True` |
| 指令匹配 | 按 `cmd_no`（`{发货单号}-R{轮次}`）反查指令，回填 delivery_id / wms_bill_no |
| 回传登记 | `ful_outbound_callback`（只增不改，含 reject_reason / process_status） |
| 应答回执 | 发布 `wms.outbound.callback` / `.accepted` / `.rejected` / `.recall.succ` / `.recall.failed` |

### 2.3 通道侧状态投影（§4.2）

```
已受理 → 下发中 → 已下发 → WMS作业中 → 部分回传 → 回传闭环 → 编排完成
                    ↓                ↓
                 重试中            已打回
                    ↓
                 下发失败
```

**关键修正**：出库回传后不能一律置 `partial`——按**累计回传量 vs 指令量**判定：
- 齐套（Σ实发 ≥ Σ指令）→ `completed`（回传闭环）
- 不齐套 → `partial`（等尾批）

口径实现见 `OutboundCommandService._outbound_cmd_status`，测试 `test_outbound_cmd_status_closed_when_fulfilled` 守住。

### 2.4 事件驱动编排

```
WMS 回传 → bas_event_outbox → WmsEventDispatcher.dispatch_pending()
  ├─ wms.outbound.pushed     → D03.07 transit(push)
  ├─ wms.outbound.accepted   → D03.07 transit(callback_ack) → processing
  ├─ wms.outbound.callback   → D03.07 handle_callback（七步编排）
  │     ├─ 行匹配 → settle 转扣减 → 差异登记 → 包裹落库
  │     └─ 状态流转 → 订单行 sendnum 回写
  ├─ wms.outbound.rejected   → D03.07 transit(reject) → rejected
  ├─ wms.outbound.recall.succ/.failed → 叫回结果
  └─ order.delivery.shipped  → D02.04 平台发货回传
```

事件无主（缺 delivery_id）时**跳过并告警**，不阻断其他事件。

### 2.5 平台发货回传（D02.04）+ 失败重试（D02.05）

| 项 | 实现 |
|---|---|
| 触发 | `order.delivery.shipped` 事件（发货确认时发布） |
| 台账 | `gw_writeback_task`（幂等键 = 发货单号 + 动作） |
| 动作 | `taobao.logistics.online.send`（统一方法名 → 适配器映射为平台原生名） |
| 结果回写 | 发货单 `sync_status`：`none/run/succ/fail` + `sync_msg` |
| 失败分级 | `gw_api_fail.err_level`：`RETRYABLE` / `RATE_LIMITED` / `AUTH` / `MANUAL` / `FATAL` |
| 重试调度 | `retry_pending()` 按 `next_retry_time` 取待重试，退避序列复用 D02.05 |

## 3. WMS 模拟器（`mocks/wms/`）

### 3.1 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/wms/restful/outbound` | 通天晓风格出库指令受理（幂等） |
| POST | `/wms/restful/cancel` | 通天晓风格叫回指令 |
| POST | `/wms/restful/query` | 单据反查 |
| POST | `/wms/qimen/{method}` | 奇门风格统一入口（deliveryorder.create / .cancel / .query） |
| POST | `/wms/callback` | WMS 主动回传（接收确认/出库回传/打回/叫回结果） |
| POST | `/sim/playback` | **状态回放**：一键推进到目标状态（accepted/outbound/partial/rejected/recall_*） |
| POST | `/sim/inject` | **错误预置注入**：按指令单号预置错误码（锻炼重试/终态路径） |
| POST | `/sim/pick` | 模拟拣货完成（触发叫回被拒） |
| GET | `/sim/cmds` `/sim/callbacks` | 指令池 / 回传事件（调试） |
| POST | `/sim/reset` | 清空 |
| GET | `/healthz` | 存活探针 |

### 3.2 保真点

- **单号规则**：OMS 下发单号 = `{发货单号}-R{轮次}`，模拟器据此反解原单号与轮次
- **批次幂等**：出库回传按 `wms_batch_no` 独立幂等
- **实发 ≠ 指令**：`/sim/playback` 的 `actual_num` 覆盖 → 驱动 D03.07 少发/多发差异登记
- **分批出库**：一次指令可多批回传 → 驱动 `partial_outbound` 路径
- **错误注入**：8 类错误码（TIMEOUT / SYSTEM_BUSY / LOCK_CONFLICT / INVALID_PAYLOAD / NO_PERMISSION / WMS_CLOSED / RECALL_REJECT），覆盖 RETRYABLE / FATAL 两级

## 4. 本轮踩坑（已修）

| # | 问题 | 根因 | 修法 |
|---|---|---|---|
| 1 | **回传全部匹配不到发货单** | 事件 payload 缺 `delivery_id`，编排时 `transit(0, …)` 抛 NotFound | `_publish` 所有事件补 `delivery_id`；编排器对无主事件跳过并告警 |
| 2 | 回传行匹配全失败（settled=0） | WMS 回传用**物料编码**，发货单行用 `bm_id` | 通道层加 `_standardize_lines()`：编码 → bm_id 映射（FR-03a 解析标准化） |
| 3 | 少发差异恒为 0 | `num = min(actual, remain)` 已截断，`actual < num` 永不成立 | 判定基准改为**指令量**（未核销口径）vs 实发量 |
| 4 | 叫回报「指令不存在」 | 叫回单号另起 `-C1`，WMS 按原单拦截 | 叫回引用原 push 单号 `{发货单号}-R1` |
| 5 | 路由查询 SQL 报列不存在 | `COALESCE(b.app_key,'')` 无别名 → 结果列名非 `app_key` | SQL 加别名 |
| 6 | 模拟器响应解析失败 | 模拟器 `code` 是**字符串**（如 `wms.timeout`），代码按 int 转换 | 解析兼容字符串码 + `err_class` 兜底分类 |
| 7 | 重试次数统计恒为 0 | `_bump_retry` 用 COUNT 历史 waiting 记录数，非本指令当前次数 | 改为按本指令计数 |
| 8 | **通道侧状态一律 partial** | 未按 §4.2 区分「回传闭环 / 部分回传」 | 新增 `_outbound_cmd_status()`：累计回传量 ≥ 指令量 → `completed` |
| 9 | 通道轨迹查询列名偏差 | `spendtime_ms`（非 spend_ms）/ `callback_type`（非 cb_type）/ `fail_reason`（非 err_msg）；`ful_cmd_fail` 无 `delivery_bn` | 逐列核对真实 DDL 后改写 |
| 10 | 演示数据跨轮被幂等挡掉 | 回传幂等键 = 发货单号 + 批次，固定单号重复 | 单号带轮次后缀；清理顺序改为「先通道表后发货单表」 |
| 11 | 测试顺序依赖导致随机失败 | `order_bn` 用 `time_ns() % 1e8` → 10 秒内重复 | 改为时间戳后 8 位 + uuid 前 6 位（≤ varchar(32)） |
| 12 | 差异演示不出来 | 分批发货时整行漏发属正常，不登记差异 | 改为「同行量差」场景：指令 2 件 / 实发 1 件 → short 差异 |

> **规律沉淀**：DDL 列名偏差在本轮又出现 2 次（通道四表）。已固化为 `tools/check_model_ddl.py` 自动门禁（逐表逐列比对 ORM ↔ information_schema），CI 复演每次必跑。

## 6. 自验方式

```bash
# ① 启动模拟器
cd KT-OMS
python3 tools/daemon.py /tmp/wms.pid /tmp/wms.log \
  backend/.venv/bin/python -m uvicorn app.main:app --app-dir mocks/wms --host 127.0.0.1 --port 9001

# ② 装配演示数据（真实推仓 → 回放 → 回传 → 确认 → 平台回传）
cd backend && .venv/bin/python -m app.scripts.seed_wms_demo

# ③ 启动前后端
python3 tools/daemon.py /tmp/be.pid /tmp/be.log \
  backend/.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
python3 tools/daemon.py /tmp/web.pid /tmp/web.log node tools/serve_frontend.mjs 5173
```

访问 `http://127.0.0.1:5173`（admin / Ktoms@2026）→ 左侧「发货单工作台」→ 双击 `DLVW7DEMO*FULL` 单 → **WMS 通道轨迹** 页签。

演示数据形态：

| 发货单 | 状态 | 通道痕迹 |
|---|---|---|
| `*FULL` | 已发货（shipped） | 指令 completed + 回传 2 条（accepted/outbound）+ 平台回传 succ |
| `*PART` | 部分出库（partial_outbound） | 指令 partial + 回传 2 条 + 差异登记（short 1，责任方 wms，补发） |
| `*FAIL` | 草稿（推仓失败） | 指令 failed + 失败台账（RETRYABLE，wms.system-busy） |
| `*DRAFT` | 草稿 | 未推仓 |
